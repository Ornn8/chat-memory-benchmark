# 计分方法（成绩 + 成本）

下面这一节是 2.1 挑战赛的正式计分规则，按原文公布。系数 3 和下限 1/4 是配置项（`harness/bench21/score_config.json`），改动必须在这里公告。

每个榜分别计算：

- **成绩 A**：封存集得分（%），按真实流量加权（不加权的分数也列出来）。
- **成本 C**：跑完这个榜全部封存题的总花费，单位人民币。由评测程序计量，不收自报的数：
  - 记忆系统的每一次模型调用（对话模型、向量、重排）都必须经过评测程序提供的网关（`OPENAI_BASE_URL` 一类的环境变量）。
  - 网关按 token 数乘仓库里固定的价目表 `prices.json`（带版本号）计价。用哪家的模型就按那家的官方标价；本地模型按 DeepSeek flash 的价格计价，避免本地跑就算 0。
  - 写入（逐轮存记忆）和读取（每道题的检索）都算。
  - 塞进答题提示词里的记忆内容，也按 flash 的输入价算进 C。这样「全塞」的成本就能体现出来。
  - 延迟只列出，不计分。
- **综合分 S = A − 3 × log2(C / C_ref)**
  - C_ref = 我们 Qwen r3 在这个榜的成本。
  - 意思是：成本每翻一倍扣 3 分，每减一半加 3 分。
  - C 不低于 C_ref / 4，所以省钱最多加 6 分，防止「什么都不记、成本接近 0」的系统靠省钱冲上去。
- **总排名**：三个榜 S 的加权平均——短对话榜 37.5%、长对话榜 37.5%、自然用记忆榜 25%（权重在 `score_config.json` 的 `board_weights`）。榜单上 A、C、S 三列都显示，再加一张成绩—成本散点图（标出帕累托前沿）。自然用记忆榜的 C_ref 是我们的 Qwen r3 在**该榜**上的 C。
- **奖品条件**（四条都要满足）：
  1. 三个榜的加权平均 S 第一；
  2. 三个榜的加权平均 A 也高于我们的 Qwen r3（不能只靠省钱赢）；
  3. 用宽松许可证开源，并且所有调用都走网关（开源后可以复查）；
  4. 自然用记忆榜的资格底线：克制率 ≥ 70% 且编造率 ≤ 5%（配置项 `floor_restraint_pct`、`floor_fabrication_pct`）。
  截止日期：2026-12-09 23:59（北京时间，自 2026-11-09 公布起一个月）。

## 实现细节（程序里怎么做的）

- **通过规则**：判分模型只报告事实（每条 required 是否满足、有没有命中 forbidden / 诱惑性编造 / 把未知当已知 / 日期错 / 该答却推说不记得 / 编造事实细节）；通过与否由脚本算：所有 required 都 met 且没有任何命中。
- **成绩 A**：主题题（`kind=main`）的通过率。对照题（旧版「不该引用个人内容」）单列，不进 A。新题里的「触发 / 不触发」「到期 / 非到期」对照题属于主题题，计入 A。
- **流量加权 A**：按最近一次相关提及离提问的时间分六箱——1 小时内 54%、当天 25%、1–3 天 9%、4–7 天 5%、8–30 天 6%、30 天以上 1%（来自真实用户需求统计，见 `docs/`）；每箱的总权重固定为这个比例，箱内平均分；`severity=severe` 的题（姓名、生日、明确约定、明确边界、否认有证据的事、隐私泄露）权重 ×2。某箱没有题时其余箱按比例放大。不加权的 A 同时列出。
- **成对分**：时间孪生、真假前提孪生、条件孪生、到期 / 非到期对照，每一对两题都通过才算过；单独列出，不进 S。
- **C 的组成**：①系统自己的模型调用（逐轮写入的向量、每题的检索向量、重排、记忆系统内部用的对话模型），由网关逐次计量；②答题提示词里的记忆文本，token 数 = 答题调用的 prompt_tokens × 记忆文本字符数 ÷ 整个提示词字符数，按 flash 输入价计。答题和判分本身的调用不进 C。
- **价目表**：`harness/bench21/prices.json`，带版本号。缓存命中的调用照样按全价计入 C（只是不重复花真钱），所以 C 只取决于「调用了多少 token」。
- **C_ref**：我们的 Qwen r3 在该榜封存集上的 C。榜单更新时 C_ref 固定为公布的值。
- **泄漏哨兵**：评测程序按截止轮从小到大访问考点，只把截止轮之前的历史一轮一轮喂给系统；检索结果里出现截止轮之后的轮次直接判泄漏。另外在若干考点的「截止轮之后一轮」埋了金丝雀（复读题面并带唯一编号），金丝雀出现在检索结果里即判失败。时间孪生的早期题还自带语义哨兵：回答或记忆文本里出现只在截止轮之后才说过的内容，同样标记为泄漏。泄漏的系统成绩作废。


## 自然用记忆榜的计分

题型五类：**X** 该提的时候要提（占 40%）、**H** 只记得一部分或根本没说过、要说拿不准（10%）、**Y** 不该提的时候不要提（30%，含：他难过时不翻旧账、陈年小事不反复提、被叫停的事不再提、已完成或被更正的事不再催/不用旧版本、敏感的事不主动带出）、**Z** 提不提都行（10%）、**N0** 无关闲聊、不该硬塞旧事（10%）。

判分员（DeepSeek flash，温度 0，关闭思考）对每一轮回复只报事实：是否在回应当前这句、是否用上了应该用的旧事、细节对不对、是否带出了不该带出的旧事、其他回忆（再用历史检索核查有没有依据）、是否表达了不确定、是否编造。「提旧事的口吻」另用一次调用打 0/1/2（数据库口气 / 生硬 / 像人）。每一题的得分（0–1）：

- X：编造或没回应 → 0；没用上 → 0；用上但细节错 → 0.2；用上且对 → 0.8 + 0.2 × 自然度/2。
- H：编造 → 0；明确表达了拿不准/就缺的部分问了一句 → 1；H1/H3 里把记得的部分说对但没表达不确定 → 0.7；其他 → 0。
- Y：编造或没回应 → 0；没带出不该带的旧事 → 1；带出了 → 1 − 严重度（低落时翻旧账、被叫停的事、隐私 = 1.0；陈年小事重复、旧版本 = 0.8）。多轮题里同一件不该提的事被提了两次以上，整题不超过 0.3。
- Z：没提 → 1；提了且对且不生硬 → 1；提了但生硬 → 0.5；提错 → 0。
- N0：没提旧事 → 1；硬塞旧事 → 0.4；编造 → 0。

**A（自然用记忆榜）** = 五类得分按 40 / 10 / 30 / 10 / 10 加权平均 × 100，类内严重题（姓名、生日、约定、健康、隐私、明确边界）权重 ×2；同时列出不加权的平均和按真实情绪占比（低落 4.2% / 开心 21.6% / 平常 74.2%，来自聚合统计）还原的版本。**C** 的算法与另两个榜相同（系统自己的调用 + 记忆文本按 flash 输入价；写入历史、读取每道题都算，尾巴里的写入和检索也算）。

另外列出的子分：想起率（X 题中用上旧事的比例）、克制率（Y 与 N0 题中没乱提的比例）、编造率（所有被评回复中编造的比例）、拿不准通过率（H）、自然度均值。其中克制率和编造率是奖品的资格底线。
