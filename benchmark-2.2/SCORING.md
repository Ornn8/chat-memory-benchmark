# 计分方法（2.2）

系数和权重是配置项（`harness/bench22/score_config.json`），改动必须在这里公告。**2.2 的分数不能和 2.1 直接比较**：历史更密、题量更大、计分也变了。

## 一、短对话榜和长对话榜

### 成绩 A

1. **通过规则**：判分模型（DeepSeek V4.1 flash，温度 0，关闭思考）只报告事实——每条 required 是否满足、有没有命中 forbidden / 诱惑性编造 / 把未知当已知 / 日期错 / 该答却推说不记得；通不通过由脚本算：所有 required 都 met 且没有任何命中。
2. **计分单元**：普通题自己是一个单元。**成对的题只按「对」计**：时间孪生（早/晚）、真假前提孪生、条件孪生（成立/不成立）、到期题 + 非到期对照题，两题都通过，这个单元才通过；对照题单独不给分。没有搭档的对照题不计分。
3. **日常分 D** 和 **长期分 L**：按这个单元「最近一次相关提及」离提问的时间分成两类——**日常**（1 天以内）和**长期**（超过 1 天）。成对的单元按其中较老的一题归类。每一类内都是**不加权**的通过率，严重题（姓名、生日、明确约定、明确边界、否认有证据的事、隐私泄露）算 2 份。
4. **榜单成绩 A = (D + L) / 2。** 这样「刚说过」的容易题和「隔了很久」的难题各占一半，既不被一类题的数量淹没，也不再像 2.1 那样 81% 的权重压在几十道题上。
5. **附加列**：按真实用户查询的时间分布加权的分数（`A_traffic`：1 小时内 54%、当天 25%、1–3 天 9%、4–7 天 5%、8–30 天 6%、30 天以上 1%）仍然列出，但不是排名分数；不加权的总通过率也列出。

### 95% 区间

每个公布的分数都带 95% 区间：**按事实组聚类的 bootstrap**（同一个事实组的多次问法、同一个事件族的汇总题当作一个整体重抽，2000 次，固定随机种子）。区间只反映「题目抽样」的不确定性，不包括判分模型本身的误差（见 `results/judge-checks.md`）。S 的区间 = A 的区间平移成本项（C 视为固定）。总排名的区间是三个榜各自重抽后按权重合成。

### 成本 C 和综合分 S

- **成本 C**：跑完这个榜全部题的总花费，单位人民币，由评测程序计量，不收自报的数：系统自己的每一次模型调用（对话、向量、重排）都经过评测网关，按 `harness/bench22/prices.json` 的固定价目表（带版本号）计价，缓存命中也按全价计；本地模型按 DeepSeek flash 的价格计价；写入（逐轮存记忆）和读取（每道题的检索）都算；塞进答题提示词里的记忆内容按 flash 的输入价计入。答题和判分本身不进 C。延迟只列出，不计分。
- **S = A − 3 × log2(C / C_ref)**，C 不低于 C_ref / 4（省钱最多加 6 分）。**C_ref = Qwen 基础方案（qwen-base）在这个榜的 C。**
- 费用：每次运行先交 ¥50 押金，按这次运行的实际费用（你的系统 + 答题 + 判分）结算、多退；总费用到 ¥50（配置项 `run_cost_ceiling_cny`）即停、无成绩，不补交。账单和这里的 C 是两回事：C 只算你的系统自己的调用和记忆文本。

### 总排名

**总分 = 0.25 × S（短对话榜）+ 0.25 × S（长对话榜）+ 0.5 × S（自然用记忆榜）**（权重在 `board_weights`）。榜单上 A、C、S 都显示，再加成绩—成本散点图。

## 二、自然用记忆榜

题型五类：**X** 该提的时候要提、**H** 只记得一部分或根本没说过、要说拿不准、**Y** 不该提的时候不要提、**Z** 提不提都行、**N0** 无关闲聊不硬塞旧事。**标签规则很严**：X 只在「好朋友在这里明显会自己带出，不提就像不了解他」时成立；Y 只在「提起来明显不受欢迎或没意义」时成立；通情达理的人提也行不提也行的，一律是 Z 或者不出。X 的子类除了 2.1 的（X1 说到未来的事、X2 习惯变过、X3 长期状况、X4 今天到期、X5 事后追问、X6 偏好运用）外，新增：X7 几天前他不开心的事、这次他开口很平常（轻轻问一句）；X8 她自己答应过的事到期了；X9 两人之间的梗或称呼（用在合适处，不硬塞）。至少四分之一的题是多轮（B 档）：要记得或要避开的事分几轮出现，包括他中途纠正她。

判分员对每一轮回复只报事实（是否回应当前这句、是否用上了该用的旧事、细节对不对、是否带出了不该带的旧事、是否表达了不确定、是否编造），口吻另打 0/1/2（数据库口气 / 生硬 / 像人）。每题得分：

- X：编造或没回应 → 0；没用上 → 0；用上但细节错 → 0.2；用上且对 → 0.8 + 0.2 × 自然度 / 2。
- H：编造 → 0；明确表达了拿不准 → 1；记得的部分说对但没表达不确定 → 0.7；其他 → 0。
- Y：编造或没回应 → 0；没带出不该带的旧事 → 1；带出了 → 1 − 严重度（低落时翻旧账、被叫停的事、隐私 = 1.0；陈年小事重复、旧版本 = 0.8）。多轮题里同一件不该提的事被提两次以上，整题不超过 0.3。
- Z：没提 → 1；提了且对且不生硬 → 1；提了但生硬 → 0.5；提错 → 0。
- N0：没提旧事 → 1；硬塞旧事 → 0.4；编造 → 0。

**A（自然用记忆榜）= 想起侧 R 与克制侧 P 的调和平均。** 每类内按题加权平均（严重题 ×2）：m_X、m_H、m_Y、m_N0、m_Z；R = (0.40 m_X + 0.10 m_H) / 0.50，P = (0.30 m_Y + 0.10 m_N0 + 0.10 m_Z) / 0.50，A = 100 × 2RP / (R + P)。一个系统必须同时「该提时提」和「不该提时不提」才能拿高分。95% 区间按「题目所依据的事实组」聚类 bootstrap。C、S 的算法与另两个榜相同（C_ref = qwen-base 在本榜的 C）。

**编造的认定**（对所有系统一视同仁，两步）：第一步判分员标出可疑处；第二步由另一次调用复核，只认真正的编造（把历史依据里没有或相反的具体过去的事说成说过 / 做过），复核确认的才计入。原始标记保存在判分记录的 `fabrication_raw`，复核引文在 `fabrication_quote`。

**资格底线**（不进 S，只是奖品条件）：克制率（Y 与 N0 题里没乱提的比例）≥ 70%，编造率（所有被评回复中编造的比例）≤ 5%。

**两项诊断（每个系统在 X 类探针上，和得分并排列出）**：①「需要的记忆进了提示词吗」——这道题所依据的历史轮次有没有出现在系统交给答题模型的记忆文本里；②「进了之后用上了吗」——进了的题里，回复用上该用的旧事的比例。这两个数告诉挑战者：丢分是因为检索没找到，还是找到了没用好。到点类（X4）单独再列一个「进了提示词」的比例（相似度检索天然找不到「今天是那一天」）。

## 三、实现细节

- **价目表**：`harness/bench22/prices.json`；Bailian 的向量和重排按 ¥0.5 / 百万 token（主人确认）；DeepSeek flash 的单价 $0.18 / $0.72 每百万 token 是由我们自己的账单拟合出来的，不是官方牌价。
- **泄漏哨兵**：评测程序按截止轮从小到大访问考点，只把截止轮之前的历史喂给系统；检索结果出现截止轮之后的轮次直接判泄漏；另外在若干考点的「截止轮之后一轮」埋金丝雀，金丝雀出现在检索结果里即判失败。时间孪生的早期题自带语义哨兵。泄漏的系统成绩作废。
- **开发集 ≠ 榜单成绩**：开发集公开，高分容易调出来。`results/` 里把我们自己基线在开发集和封存集上的分数并排列出，请用封存集的数看。
