# 中文陪伴记忆 Benchmark 2.2

两个合成人物、各半年（2026-09-01 至 2027-02-27）的聊天历史，三个榜：**短对话榜**（M01 宋雨橙，话痨短句型）、**长对话榜**（M02 孟远舟，长信型）、**自然用记忆榜**（该提旧事时提，不该提时不翻旧账，提的方式像人）。成绩和成本一起排名。

> **状态：挑战赛还没有开始。** 它在主人公开宣布的那一天、按 2.2 开始。2.1 阶段写过的截止日期和「已经开始」的说法都不作数。规则见 [RULES.md](RULES.md)，计分见 [SCORING.md](SCORING.md)。

## 先读这四条

1. **开发集分数不是榜单成绩。** 开发集的题面、评分标准和参考答案都是公开的，高分很容易调出来（例如 2.1 短对话榜上，同一个 Qwen 基础方案的开发集加权分是 68.5，封存集是 58.5）。看榜单请看封存集一列；我们自己的基线在开发集和封存集上的分数并排列在 [results/README.md](results/README.md)。
2. **2.1 和 2.2 的分数不能直接比较。** 2.2 的历史更密（同样半年里，M01 从 3000 轮增到约 7000 轮，M02 从 2500 轮增到约 5400 轮——更多干扰），题量大约翻了一倍半，题型比例变了，计分也变了（日常分与长期分的平均，成对题只按「对」计，每个分数带 95% 区间）。
3. **每个分数都带 95% 区间**：按事实组聚类的 bootstrap，只反映「抽到哪些题」的不确定性，不包括判分模型本身的误差。差距在区间之内，就不要说谁更好。
4. **只有两个合成人物。** 结果反映的是这两个人物、这半年的历史，不等于任何真实用户群的体验；所有对话和题目都是合成的，没有使用任何用户的原文。

## 2.2 相比 2.1 变了什么

- **历史更密**：同一个半年里插入新的会话（原有每一轮对话一字不改，只是重新编号），M01 约 7000 轮、M02 约 5400 轮；设计里的长沉默保留；新增约各 100 个事实组，来自各 10 个新事件族（瑜伽课、学做饭、看病/跑现场、投标……），与原台账不矛盾。
- **题量**：每个榜封存题 ≥ 600、开发题 ≥ 300；其中最近一次相关提及在 1 天内的（日常）和超过 1 天的（长期）各 ≥ 300（封存集）；到点主动提起、暗考、聚合计数、按日期找、孪生各自有足够的题量。
- **自然用记忆榜扩到封存 552 题 / 开发 96 题**：先审计了 2.1 的全部题（两遍独立检查，改标签 85 道、删 6 道），再按更严格的标签规则新写；至少四分之一是多轮题；新增三类情境（几天前他不开心的事、她自己答应过的事到期、两人的梗或称呼）。
- **计分**：A = 日常分与长期分的平均；对照题只按「对」计；95% 区间；参照系统是 Qwen 基础方案；总分 = 短 25% + 长 25% + 自然用记忆 50%。
- **自然用记忆榜新增两项诊断**（和得分并排）：需要的记忆进了提示词吗、进了之后用上了吗。
- **挑战赛规则**：开源参赛、固定 commit、我们干净检出运行、一次封存跑、每个参赛系统自己的模型用量最多 ¥50（网关强制）、一轮结束公开封存题和全部回答。

## 怎么跑

```sh
git clone https://github.com/Ornn8/chat-memory-benchmark.git
cd chat-memory-benchmark/benchmark-2.2
python dataset/read_exam_v22.py                      # 离线校验（不需要密钥）
python -m unittest discover -s ../tests -p "test_bench22*.py"
```

评测程序和适配器接口见 [harness/README.md](harness/README.md)。所有模型调用必须走评测网关。

## 隐私

全部为合成数据：人物、对话、题目都是生成的。自然用记忆榜的题目分布参考了已同意「帮助改进」的用户的聚合统计（比例、间隔、话题），没有使用任何用户原文。发布前做过密钥、邮箱、本地路径、手机号 / QQ 号扫描，见 [results/README.md](results/README.md) 末尾。
