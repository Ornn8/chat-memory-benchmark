# 2.2 结果

> **这是一份不完整的榜单，先看这一节。**
> 1. **Qwen 基础方案（参照系统）这次没有跑。** 本机的百炼（DashScope）账号欠费，向量和重排调不通；所以 **没有 C_ref，榜单里所有 S 和总分都空着**（A 和 C 都有）。参照行补跑后，S 和总排名由 `harness/bench22/report.py` 直接算出，不需要改任何别的东西。
> 2. **只是基线。** 下面是我们自己的几个基线：无历史、只看最近 6 轮、BM25 + 最近 6 轮；自然用记忆榜另有「从不提」「见缝就提」，和一条全塞（抽样）。没有任何外部系统的成绩。
> 3. **按抽样打分。** 费用上限（人民币 100 元）用完了，所以短 / 长对话榜按一个固定随机抽样打分（封存集每个榜约 300 题、开发集约 120 题，成对的题一起抽；所有系统用同一批题）；自然用记忆榜的基线是全部题，全塞只跑了 60 道封存题（C 按全部题折算）。全塞在短 / 长对话榜上**没有跑**。
> 4. **所有分数都带 95% 区间**，区间只反映抽到哪些题；两个分数的区间重叠，就不要说谁更好。**开发集分数不是榜单成绩**，见下面的并排表。**2.1 和 2.2 的分数不能直接比较。** 结果只反映这两个合成人物。

## 4. 自然用记忆榜的诊断

见上面榜单下方的「两项诊断」表。要点：BM25 + 最近 6 轮里，只有大约一半 X 题的「需要的记忆」进了提示词（到点类的只有约 5%：相似度检索天然找不到「今天是那一天」）；进了的，有约七成用上了。也就是说，这一榜的失分既有检索（约一半没进提示词），也有用法（进了的约三成没用上）。

## 5. 成本

C 是跑完这个榜全部题的人民币成本（系统自己的调用 + 记忆文本按 flash 输入价，价目表 prices-2.2.0；答题和判分不算）。本地基线没有模型调用，C 只有记忆文本的部分。

**一次封存跑要花你多少钱（Qwen 基础方案，估算，未实测）**：Qwen 基础方案的每个调用都是百炼向量 / 重排（¥0.5 / 百万 token）。按 2.1 里实测的 token 数随历史长度放大（2.2 的历史大约是 2.1 的 2.3 倍长），写入约 ¥0.2（短）/ ¥0.9（长），每题检索（重排为主）约 ¥0.0015 / ¥0.006，一个榜约 900 题：**系统自己的用量约 ¥1.5–2（短对话榜）、¥6–7（长对话榜）**，远低于 ¥50 的上限；加上记忆文本进答题提示词的钱，C 约 ¥4–5（短）、¥15–17（长）。这是估算，等百炼账号恢复后用实测值替换。

## 6. 判分员校准（flash vs 独立阅读）

从基线回答里取 192 项（判分员判过 / 没过各约一半，来自 2.2 新题）；让 4 个独立的 Sonnet 读者在**不知道判分结果**的情况下，按同一份评分标准逐条判断是否通过。一致率 **92.7%**，Cohen's κ = **0.85**（判分员判过而读者判不过 8 项，反过来 6 项；判分员通过率 49.5%，读者 48.4%）。
说明：读者是模型，不是人；样本按判分结果对半抽，所以通过率不代表真实分布；这是在基线的回答上测的，高分系统的回答（更长、更细）上一致率可能更低。

## 7. 泄漏哨兵

bm25-recent6，封存集 24 个考点（每个榜 12 个），在截止轮之后一轮埋金丝雀：**强制隔离 0/24 看到未来内容；故意泄漏的正对照 24/24**（原始结果见 `sentinel-*.json`）。Qwen 的哨兵没跑（同上，账号欠费）。

## 8. 我们验证了什么、没验证什么

- 验证了：评测程序的计分单元、日常 / 长期分、聚类 bootstrap、成本上限（13 个单元测试）；历史里原有每一轮一字不改（脚本逐轮核对）；每道新题的证据在截止轮之前；每道新题至少让另一家模型在「只给证据」或「把关键记忆放进提示」时通过（或由人工复核判为题没坏），不通过的已隔离；离线校验器 0 错误。
- **没验证**：Qwen 基础方案和任何外部系统的成绩；全塞在短 / 长对话榜；用更强判分员的复核；人类对题目的逐条审阅（复核是模型做的，我们只抽查）；这些题对真实用户的代表性（只有两个合成人物）。生成的聊天历史里同一件事的日期、先后有不少前后矛盾，出题时尽量避开，但没有逐条审完整份历史。
