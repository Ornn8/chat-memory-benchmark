## 比什么

- 三个榜。前两个各用一个合成人物的完整聊天历史（两人都是半年、2026-09-01 至 2027-02-27）：
  - **短对话榜**：M01 宋雨橙（话痨型，短句，约 7000 轮）。
  - **长对话榜**：M02 孟远舟（长信型，约 5400 轮）。
  - **自然用记忆榜**：在同样两个历史上，测系统有没有**自然地**使用记忆——该提的时候主动提、不该提的时候不翻旧账、提的方式像人、拿不准就说拿不准而不编。**题目设计参考了已同意「帮助改进」的用户数据的聚合统计（比例、间隔、话题分布）；没有使用任何用户的原文，所有对话和题目都是合成的。**
- 每个榜有公开的**开发集**（题面、评分标准、参考答案都公开，可以随便调系统）和不公开题面的**封存集**（正式成绩只看封存集）。封存集的 SHA256 承诺写在 `dataset/sealed-commitment.json`。
- 成绩与成本一起算，计分方法见 [SCORING.md](SCORING.md)：每个榜的综合分 S = A − 3 × log2(C / C_ref)，C_ref 是 Qwen 基础方案（qwen-base）在该榜的成本；总排名是三个榜 S 的加权平均：短对话 25%、长对话 25%、自然用记忆 50%。
- **2.1 和 2.2 的成绩不能直接比较**：2.2 的历史更密（同样半年里的轮数大约翻倍），干扰更多，题量更大，计分也变了。

## 奖品

一个 200 美元的 ChatGPT 订阅。同时满足下面全部条件才有资格：

1. 总排名综合分 S 在决赛里最高；
2. 三个榜的加权平均成绩 A 高于 Qwen 基础方案（不能只靠省钱赢）；
3. 自然用记忆榜的资格底线（不进 S，只是条件）：克制率 ≥ 70%，编造率 ≤ 5%；
4. 用宽松许可证开源（MIT / Apache-2.0 / BSD 等），所有模型调用都走评测网关；
5. 领先第二名的幅度超出 bootstrap 区间；如果没有超出，成本低（C 小）的胜；成本也一样则并列。

时间：2026-11-12 起四周（见上面的时间表），目标 2026-12-12 公布结果。我们自己的系统是基线，不参加比赛。

## 参赛系统必须遵守

1. **只通过网关调用模型。** 对话模型、向量模型、重排模型的每一次调用都必须发往评测程序给出的网关（环境变量 `OPENAI_BASE_URL`，路径 `/chat/completions`、`/embeddings`、`/rerank`）。网关持有供应商密钥，按 `harness/bench22/prices.json` 的固定价目表给每次调用计价。**参赛者不需要、也不能提供密钥**：所有调用都走我们的网关，费用记在你这次运行的账上（见下一条）；自带密钥直连供应商的，查出来取消资格。本地模型要放在网关后面：用 OpenAI 兼容服务起本地模型，在网关上设置 `BENCH22_LOCAL_URL`，系统里以 `local:模型名` 调用；网关按服务返回的 token 数记账，按 DeepSeek flash 的价格计价。
2. **费用：¥50 押金，按实际费用多退，超过 ¥50 成绩作废。** 测试费用由参赛者自己出。每次运行之前——调试期那一次开发集试跑、第 4 周那一次封存跑——先交 ¥50 押金。运行结束后，我们按公布的价目表，对这次运行的**实际费用**结算：你的系统通过网关的全部模型调用，加上答题、加上判分。押金有剩就退还剩下的部分。**每次运行的账单随成绩一起公布，分三项列出：你的系统 / 答题 / 判分。**
   - **¥50 封顶，没有补交。** 一次运行的总费用（你的系统 + 答题 + 判分）到 ¥50，网关就停止这次运行（配置项 `run_cost_ceiling_cny`，在网关里强制执行，有测试）。停止的运行**没有成绩**，押金不退、也不再多收，你不会欠我们任何钱。没有「补交继续跑」，也不能事先加押金提高上限。
   - **账单和成绩里的 C 是两回事。** C 只算你的系统自己的调用和它放进答题提示词的记忆文本（见 [SCORING.md](SCORING.md)）；账单还要加上答题和判分。
   - **怎么付款。** 通过 issue 报名后私下约定；仓库里没有收款码，也不要求任何个人资料。
3. **记忆隔离。** 评测程序按截止轮从小到大访问考点，只把截止轮之前的历史一轮一轮喂给系统（`ingest(turn)`），系统从来拿不到历史文件。`retrieve(question, now, cutoff_turn)` 必须只读：不许把考题或答案写进记忆。
4. **不许读考题以外的东西。** 运行时只能拿到当前这一道题的 `question`、`now`、`cutoff_turn`。不得读取封存集题库、评分标准、其他考点的内容。
5. **泄漏哨兵。** 评测程序会在若干考点的「截止轮之后一轮」埋金丝雀，并检查时间孪生早期题是否出现只在截止轮之后才说过的内容。看到未来内容的系统，成绩作废并公开标注。
6. **自然用记忆榜的接口**：除 `ingest` / `retrieve` 外，系统要支持 `mark()` / `rewind(token)`：评测程序在截止轮之后喂给系统一小段合成的「尾巴」（有的由系统自己的回复现场接上），答完要求系统退回到 `mark()` 时的状态。不能回退的系统，评测程序从头重放历史（相同输入只计一次费）。另一题的尾巴出现在本题的记忆文本里即判污染，成绩作废并公开标注。
7. **到期主动提起题**（用户只说一句无关的话，好的回答要主动带出今天到期的事）考的是「主动使用记忆」：参赛系统可以在每次回复前做任何基于时间的检索或扫描，这是允许的。
8. 答题模型和判分模型由评测程序统一提供（DeepSeek V4.1 flash，温度 0，关闭思考），参赛系统只提供「记忆文本」（`Retrieval.prompt`）。记忆文本的 token 按 flash 输入价计入 C。

## 防作弊与审查

- **开源参赛，固定 commit。** 参赛系统必须开源在一个固定的 commit / tag 上。我们从干净检出运行，除了计量网关以外没有任何网络。
- **人物专用数据或提示词取消资格。** 历史是公开的，所以防「预先烤进人物知识」靠两样：开源规则，和我们对固定 commit 的审查。条目里出现任何针对 M01 / M02 的专用数据、专用提示词、写死的人名事实，一律取消资格。我们**没有**隐藏的决赛卷；封存集是公开承诺过的，一轮结束就整套公开。
- **不重跑的原则。** 封存跑只在我们这一侧出了问题（我们的机器、网关、上游供应商）时才重跑；参赛系统自己出错，或者想要更好的成绩，都不重跑。
- **透明。** 一轮结束时公布该轮的封存题、答案标准、每个系统的全部回答和判分；下一轮用新写的封存题。
- **更强判分员复核。** 名次靠前的系统用更强的判分模型重判，人工抽查 100 个回答。这一步重读同一次封存跑，不重跑。

## 榜单怎么写

- 每一行写清楚：系统名与版本、是谁跑的、测试时间、环境（题库版本、答题 / 判分模型、检索组件）。每个分数都带 95% 区间。
- 开发集成绩**不是榜单成绩**：开发集的题面、标准和参考答案是公开的，高分很容易调出来。我们自己的基线在开发集上的分数会和封存集分数并排列出。
- 参考基线永远在榜上：Qwen 基础方案（qwen-base）、无历史、只看最近 6 轮、BM25 + 最近 6 轮、全塞（最近 110k token 窗口，可能抽样）；自然用记忆榜另有「从不提旧事」「见缝就提」两条极端基线。

## 一次运行大概要花你多少钱

押金 ¥50，按实际费用多退；总费用到 ¥50 就停、没有成绩。参考例子（Qwen 基础方案，用的是 Qwen3.7 向量和重排）：一次完整封存跑，实测折算后约 ¥36——你的系统自己的调用约 ¥16，答题约 ¥13，判分约 ¥6，离 ¥50 不算远；开发集试跑约 ¥15。这是估算，不是保证：答题的钱取决于你的系统往提示词里放多少记忆文本，系统自己的钱取决于它调了多少次模型（例如把整段历史塞进提示词，或者每轮都让大模型整理记忆，一次封存跑很容易超过 ¥50，被停止）。**先在开发集试跑和本地用价目表估算，再决定封存跑的方案。** 细节见 [results/README.md](results/README.md) 的「成本」一节。

## 怎么参赛

1. 读 [harness/README.md](harness/README.md)，实现 `System` 适配器（`ingest` / `retrieve`；自然用记忆榜再加 `mark` / `rewind`）。
2. 在开发集上自测：`python -m bench22.runner --release dataset --system your-system --split dev --run mine`；自然用记忆榜：`python -m bench22.natural run --release dataset --natural dataset/natural --system your-system --split dev --run mine`（再 `judge`、`summarize`）。
3. 报名、申请一次开发集试跑、提交冻结版本，都开一个 issue：[参赛报名 / 提交冻结版本](https://github.com/Ornn8/chat-memory-benchmark/issues/new?template=challenge-entry.yml)（调试期内可以申请一次试跑；2026-12-03 00:00 之前提交冻结的 commit / tag 和使用的模型清单）。
