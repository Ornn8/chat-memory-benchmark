## 一、被测系统是什么

whale-card 是一个本地优先的长期记忆层：SQLite 单文件（`card.db`）+ 分层池（短期 / 中期 / 长期 / 归档）+ 语义向量检索（bge-small-zh-v1.5）+ 事实三元组表 + 联想网（时间与实体邻近的边）。它不是「把历史全塞进上下文」的做法，而是每轮按查询装配一份限定 `token` 预算的上下文交给模型。

考场上它扮演被测的记忆系统；作答模型是外部的（见下）。

## 二、测试配置

| 项 | 配置 |
| --- | --- |
| 六个人物隔离 | 每个人物一张独立卡（独立 `card.db`），互不共享记忆 |
| 历史写入 | 按时间顺序把用户消息与助手回复逐轮回灌，走系统自己的写入路径（含分池、抽取、向量编码） |
| 逻辑时钟 | 按题目截止点推进进程内逻辑时间，题目之间不保存快照、不复用上一题状态 |
| 检索与装配 | 每题调用系统原生 `assemble_context(question)`，由它决定给模型的上下文（含身份块、近期对话窗口、召回块、事实块） |
| 直接对话窗口 | 由系统装配在上下文内的「近期」段，约 6 轮，计入总预算 |
| 上下文预算 | 13500 tokens（系统默认） |
| 召回条数 | 直接命中 5 条（宽口径问句放宽到 12），联想补位最多 2 条 |
| 嵌入模型 | bge-small-zh-v1.5（本地） |
| 作答模型 | DeepSeek（经 DSH 子代理；未记录精确 provider 快照） |
| 判分模型 | DeepSeek（同上），按 `grading/judge-prompt.md` 初判 |

**改过的默认参数**（相对 V5.7 之前）：事实层在 V5.7–V5.9 重做并接入装配；联想网 `ensure()` 懒建边、渲染补位；短期池容量上限停用（只保留 7 天时间窗）。这些都是通用机制改动，没有针对题号、人名或个别题目的硬编码。

## 三、判分方式（与官方流程的差异，请务必按此解读）

- 使用仓库自带的 `grading/grade.py prepare` 生成 18 个题包（`packets`），覆盖全部 714 题。
- 逐题判分由 18 个独立子代理完成，每个子代理只读一个题包 + `grading/judge-prompt.md`，输出 `reviews.jsonl` 规定的 13 个字段。
- 两个哈希（`answer_sha256`、`rubric_sha256`）一律从题包原样复制，不重新计算；`grade.py score` 校验通过，**哈希不符 0**。
- **判分者是 DeepSeek，不是 Codex**；也未做人工抽查复核。因此本成绩的口径与「Codex 初判」的记录不完全可比。
