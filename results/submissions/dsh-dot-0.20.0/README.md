## 测试配置

- 题库：`natural-timegrid-20261101-v2`，`manifest.json` SHA-256 `19b7edf73bde64067a59132f6a58b1756863a880026c1487ee8a4766a377938f`。
- 六个人物：各用一个独立的数据目录，互不共享；六个人物分六个进程并行跑。
- 写入：历史按逻辑时间逐轮回放成插件监听的会话事件（用户消息、助手回复、轮次结束），伪时钟设为该轮时间；之后发生的都是插件自己的逻辑：原话写进 transcript，建召回索引，攒满 40 行整理一次三栏笔记（关于用户 / 她自己 / 还没了的事）和人物卡，每天 23:30 当天有记录才写日记，上下文估算超过 150000 token 时交班（本次六人物都没有触发交班）。轮与轮之间按分钟触发插件自己的 60 秒定时器。
- 考试：到每题的截止时间（先完成到那时为止该做的整理），新开一个独立会话：时间行、插件注入的三栏笔记、按题目自动召回的原话，加最近 6 轮完整对话作为聊天消息；一次补全作答，不给工具。题目和回答不写回 transcript、笔记或召回索引。
- 召回：向量 `Xenova/multilingual-e5-small`（本机 ONNX）与 BM25 各取 20 条候选，交给本机重排模型 `Xenova/bge-reranker-base`，最多注入 10 条（可以更少、不补足），总长上限 1500 token；按日期分组显示，"明天、下周三"这类无歧义的相对日期由代码换算出具体日期。
- 模型：整理和作答都用 DeepSeek `deepseek-flash`（官方接口 `https://api.deepseek.com`），保持模型默认的思考模式；单次输出上限 8192 token。
- 默认参数：全部用插件默认值，未做针对本测试的调整。

## 运行情况

- 六个人物都跑完。714 次作答请求中 5 次最终失败（上表），失败原因都是 DeepSeek 接口在同一时段持续返回 HTTP 500 / 503 或超时；单次请求失败会退避重试，最多 8 次。没有为挑选答案而重试：每题只保留第一次得到的回答。
- 整理共调用 857 次，9 次失败。失败原因有两种：接口 500/503；思考模式把 8192 的输出上限用完、回复为空。失败后按插件的退避逻辑处理（批量减半、等下一批再试），这部分记录可能整理得晚一些，但原话仍在召回索引里。
- 运行时间：2026-11-07 07:07–09:02 UTC，六人物并行，约 1 小时 55 分。

## 复现

```sh
git clone https://github.com/Kevinwu901113/dsh-dot && cd dsh-dot && git checkout v0.20.0 && npm install
export DEEPSEEK_API_KEY=…
for p in P01 P12 P14 P16 P17 P20; do
  node bench/chat-memory-benchmark.mjs --dataset <chat-memory-benchmark>/datasets/natural-timegrid-20261101-v2 --out out --persona $p &
done; wait
cat out/P*/answers.jsonl > answers.jsonl
```

第一次运行会从 Hugging Face（或镜像）下载向量和重排模型。
